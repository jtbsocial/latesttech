The Problem with Built-in Windows Search

For over two decades, Microsoft has struggled to deliver a fast, reliable, and lightweight search experience in Windows. Windows Search relies heavily on background content indexing, which frequently leads to high disk usage, sluggish PC performance, and battery drain on laptops. Worse yet, native Windows Search often misses newly created files, skips system directories, or defaults to web results via Bing when you are simply looking for a local PDF file.

For professionals managing massive storage pools—NVMe SSDs, external hard drives, or Storage Spaces—native Windows Search becomes a bottleneck. Power users require instant response times, real-time file system monitoring, and precision control over file metadata.

What is Voidtools 'Everything'?

Developed by David Carpenter of Voidtools, Everything is a lightweight freeware search utility designed exclusively for Microsoft Windows. Unlike traditional desktop search applications, Everything initially focuses solely on file and folder names, allowing it to index huge file systems instantaneously.

Key highlights include:
- Real-Time Updates: File modifications, additions, and deletions reflect instantly in search results.
- Minimal Resource Overhead: A clean, unbloated C++ architecture ensures maximum speed on any computer.
- Extensible: Supports third-party plugins, custom themes, dark mode, taskbar integration via EverythingToolbar, and command-line utilities.

How Everything Works: Master File Table (MFT) Magic

How can Everything index one million files in under a second when native Windows search takes hours?

1. NTFS Master File Table (MFT) Direct Reading

When installed on an NTFS-formatted drive, Everything bypasses standard OS file crawling. Instead, it directly reads the drive's Master File Table (MFT)—a special hidden file where the NTFS file system stores metadata about every file and directory on the volume. By reading the binary MFT stream directly, Everything parses the entire disk structure almost instantaneously upon startup.

2. USN Journal Tracking

Once the initial index is built, Everything monitors the NTFS Update Sequence Number (USN) Change Journal. Whenever a file is created, renamed, or deleted, Windows logs the change in the USN Journal. Everything reads these micro-updates instantly, ensuring search results remain perfectly synchronized without requiring periodic background re-indexes.

3. ReFS, FAT32, and Network Drive Indexing

For non-NTFS volumes (such as FAT32 USB sticks, exFAT cards, or network-attached storage), Everything can perform traditional folder indexing in the background or query remote Everything servers, ensuring full coverage across all storage types.

Setting Up Everything HTTP/FTP Server & CLI

Enabling the HTTP Server for Remote Network Search

  1. Open Everything and navigate to Tools > Options.
  2. Click on HTTP Server on the left menu.
  3. Check Enable HTTP Server.
  4. Set a custom port (e.g., 8080) and configure a secure Username and Password.
  5. Access your files from any browser on your home network by visiting http://your-pc-ip:8080.

Command-Line Utility (es.exe)

By dropping es.exe into your system path, you can execute instant queries straight from Terminal or PowerShell:

es.exe -ext pdf -size +100mb "Q1 Report"

This outputs matching file paths instantly to standard output, making it ideal for automation scripts.

Everything vs. Windows Search vs. Alternatives

Everything vs. Built-in Windows Search

Windows Search indexed content contents fine for small documents, but suffers heavily from bloated database structures. Everything trades initial deep document content indexing (by default) for ultra-fast, lightweight filename and metadata querying.

Everything vs. Listary / Flow Launcher

Applications like Listary or Flow Launcher focus heavily on application launching and workflow shortcuts. Interestingly, many modern launcher tools actually use the Everything SDK under the hood to perform their file queries because nothing beats Voidtools' core engine.

Frequently Asked Questions (FAQs)

1. What makes Voidtools Everything so much faster than built-in Windows Search?

Voidtools Everything reads the NTFS Master File Table (MFT) directly from the storage drive rather than scanning files folder by folder. It indexes filenames into RAM immediately, allowing searches to run in milliseconds.

2. Is Voidtools Everything completely free and safe to use?

Yes. Everything is 100% freeware for both personal and commercial use. It contains no bundled adware, trackware, or spyware, and operates completely offline unless you choose to enable its optional web server features.

3. Can Everything search inside document contents or text files?

Yes. You can use the content: search modifier (e.g., ext:txt content:"secret key"). However, because Everything does not pre-index full text contents by default to save memory, content searches run in real-time and take longer than filename queries.

4. How do I integrate Everything directly into the Windows Taskbar?

You can install a popular open-source companion project called EverythingToolbar. This replaces the default Windows Search icon on your taskbar with a seamless Everything search box that supports dark mode and native Windows styling.

5. How does the Everything HTTP/FTP Server plugin work?

The built-in HTTP server allows Everything to host a secure web application directly from your local PC. When enabled, you can log in via any web browser on your network to search and download files stored on that desktop.
